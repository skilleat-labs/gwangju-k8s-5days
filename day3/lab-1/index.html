    실습 1. 어제 Deployment에 Service 붙이기¶

    이번 실습에서 할 것

    • ClusterIP Service를 만듭니다.
    • 클러스터 안의 임시 Pod에서 Service 이름 web으로 접속합니다.

    소요 시간 약 12분, 교안 DAY 3 섹션 1

    준비¶

    • 작업 폴더로 이동합니다. (오늘의 실습 참고)
    • 어제 만든 web Deployment를 씁니다. 없으면 STEP 1에서 다시 만듭니다.
    cd $HOME\k8s-labs\day3

    cd ~/k8s-labs/day3

    STEP 1. 어제 Deployment 확인 (없으면 apply)¶

    어제 만든 web이 남아 있는지 봅니다. READY가 3/3이면 그대로 씁니다.

    kubectl get deploy web


    NAME   READY   UP-TO-DATE   AVAILABLE   AGE
web    3/3     3            3           1d
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    NotFound가 나오거나 READY가 3/3이 아니면 아래 파일을 web-deploy.yaml로 저장하고 apply합니다. 강조한 두 줄의 라벨 app: web이 다음 STEP의 Service selector와 똑같아야 합니다.

    web-deploy.yaml
    apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:1.27
        ports:
        - containerPort: 80
    web-deploy.yaml 내려받기

    kubectl apply -f web-deploy.yaml

    deployment.apps/web created
    줄 뜻
    app: web (두 곳) Service의 selector와 똑같아야 Service가 이 Pod를 찾습니다
    replicas: 3 Pod 3개. Service가 3개로 나눠 보냅니다
    containerPort: 80 Service의 targetPort에 쓸 번호

    STEP 2. Service 만들고 확인¶

    Service YAML을 web-svc.yaml로 저장합니다. apiVersion이 apps/v1이 아니라 v1인 것에 주의합니다.

    web-svc.yaml
    apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  type: ClusterIP
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
    web-svc.yaml 내려받기

    줄 뜻
    name: web Service 이름. 이 이름이 그대로 DNS 이름이 됩니다
    type: ClusterIP 클러스터 안에서만 쓰는 주소. 생략해도 기본값입니다
    selector: app: web 이 라벨이 붙은 Pod를 찾습니다
    port, targetPort Service 80번으로 받아 컨테이너 80번으로 넘깁니다 
    kubectl apply -f web-svc.yaml

    kubectl get svc web


    NAME   TYPE        CLUSTER-IP     EXTERNAL-IP   PORT(S)   AGE
web    ClusterIP   10.96.120.5    <none>        80/TCP    5s
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    CLUSTER-IP에 IP가 보이면 성공입니다. 이 IP는 Service를 지우기 전까지 바뀌지 않습니다.

    CLUSTER-IP를 브라우저에 넣으면 안 열립니다

    ClusterIP는 클러스터 안에서만 통하는 가상 IP입니다. 내 PC 브라우저로는 열리지 않는 것이 정상입니다. 밖에서 여는 방법은 실습 3에서 합니다.

    STEP 3. 임시 Pod에서 이름으로 접속¶

    클러스터 안에 작은 임시 Pod(busybox)를 하나 띄워 web이라는 이름으로 요청합니다. --rm이라 명령이 끝나면 Pod가 자동으로 지워집니다.

    kubectl run tmp --rm -it --restart=Never --image=busybox:1.36 -- wget -qO- web


    <!DOCTYPE html>
<html>
<head>
<title>Welcome to nginx!</title>
...
</html>
pod "tmp" deleted
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    Welcome to nginx!가 들어 있는 HTML이 나오면 성공입니다. IP를 하나도 적지 않고 Service 이름만으로 접속했습니다. 이름을 IP로 바꿔 준 것이 누구인지는 실습 2에서 봅니다.

    명령은 한 줄로

    교안 화면에서는 이 명령이 두 줄로 나뉘어 있지만, PowerShell에서는 줄 끝 \가 동작하지 않습니다. 위처럼 한 줄로 복사해 입력합니다.

    옵션 뜻
    --rm 끝나면 Pod 자동 삭제
    -it 터미널에 출력을 바로 보여 줌
    --restart=Never Deployment 없이 Pod 하나만 만듦
    -- wget -qO- web 컨테이너 안에서 실행할 명령. web에 요청해 결과를 화면에 출력

    성공하면¶

    • STEP 2: kubectl get svc web에 CLUSTER-IP가 보입니다.
    • STEP 3: Welcome to nginx!가 들어 있는 HTML이 출력됩니다.

    막히면¶

    wget: bad address 'web'

    web이라는 이름을 찾지 못했습니다.

    1. kubectl get svc로 Service 이름이 정확히 web인지 봅니다.
    2. 임시 Pod를 다른 네임스페이스(-n)에 띄우지 않았는지 봅니다. 네임스페이스가 다르면 짧은 이름으로는 못 찾습니다. (실습 2)
    Error from server (AlreadyExists): pods \"tmp\" already exists

    앞에서 실행한 임시 Pod가 지워지지 않고 남아 있습니다. 지우고 다시 실행합니다.

    kubectl delete pod tmp
    error: resource mapping not found ... no matches for kind \"Service\" in version \"apps/v1\"

    Service의 apiVersion을 apps/v1로 썼습니다. Service는 v1입니다. 파일을 고치고 다시 apply합니다.

    error converting YAML to JSON: yaml: line N: found character that cannot start any token

    YAML 들여쓰기에 탭 문자가 들어갔습니다. 들여쓰기는 스페이스 2칸으로만 합니다. VS Code로 파일을 다시 만들거나 내려받기 링크를 씁니다.

    wget: can't connect to remote host (10.96.x.x): Connection refused

    Service는 있는데 Pod까지 연결이 안 됩니다. 아래 둘을 확인합니다.

    • targetPort가 컨테이너가 실제로 듣는 포트(nginx는 80)와 같은지
    • selector가 Deployment의 라벨 app: web과 글자 하나까지 같은지. selector에는 Deployment 이름이 아니라 Pod 라벨을 적습니다.

    이런 연결 장애를 찾는 방법은 실습 4에서 자세히 합니다.

    If you don't see a command prompt, try pressing enter. 다음에 아무것도 안 나옴

    busybox 이미지를 처음 내려받는 중이거나, 출력이 붙기 전에 명령이 끝난 경우입니다. 10초쯤 기다려도 그대로면 Ctrl + C로 끝내고, kubectl delete pod tmp 후 다시 실행합니다.

    Windows 메모장으로 저장했더니 web-svc.yaml.txt가 됨

    메모장은 이름 뒤에 .txt를 붙입니다. 저장할 때 파일 형식을 모든 파일로 바꾸고 이름을 "web-svc.yaml"처럼 큰따옴표로 감쌉니다. VS Code를 쓰면 이 문제가 없습니다.
