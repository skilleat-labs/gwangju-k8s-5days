    2일차 오늘의 실습¶

    오늘 할 것

    • 내 노트북의 쿠버네티스 클러스터에 접속하고, 구성요소를 직접 찾아봅니다.
    • Pod를 명령형과 선언형(YAML) 두 가지로 만들고, 안을 들여다봅니다.
    • Deployment로 Pod 개수를 지키고(자가복구), 늘리고 줄이고(스케일링), Pod를 하나씩 새 버전으로 바꾸고 되돌립니다(롤링 업데이트, 롤백).
    • 컨테이너 재시작(kubelet)과 Pod 재생성(ReplicaSet)을 구분해서 봅니다.

    1일차에 도커로 겪은 한계 가운데 2번 "죽으면 아무도 안 살린다"와 3번 "하나 더 띄우려면 포트를 바꿔야 한다"가 오늘 풀립니다.

    사전 과제 확인¶

    2일차는 쿠버네티스가 켜져 있어야 시작할 수 있습니다. 아래 명령에서 docker-desktop이 Ready로 나오는지 먼저 확인합니다.

    kubectl get nodes


    NAME             STATUS   ROLES           AGE   VERSION
docker-desktop   Ready    control-plane   1d    v1.3x.x
    출력은 예시입니다. AGE와 VERSION은 사람마다 다릅니다.

    오류가 나거나 노드가 안 보이면 Kubernetes 켜기를 지금 따라 합니다. 처음 켤 때 몇 분 걸리니, 켜지는 동안 강의를 들으며 기다리면 됩니다.

    작업 폴더¶

    오늘 실습은 모두 k8s-labs\day2 폴더에서 합니다. 터미널을 열고 아래 명령으로 폴더를 만들고 이동합니다.

    하루를 마칠 때 정리¶

    실습 4까지 만든 Pod web, web2는 실습 4 끝에서 지웠습니다. 혹시 남아 있으면 지웁니다. 이미 없으면 --ignore-not-found 덕분에 오류 없이 넘어갑니다.

    kubectl delete pod web web2 --ignore-not-found

    남은 것을 확인합니다.

    kubectl get all


    NAME                       READY   STATUS    RESTARTS   AGE
pod/web-7c5b8d9f6d-4xk2p   1/1     Running   0          10m
pod/web-7c5b8d9f6d-9qz7m   1/1     Running   0          10m
pod/web-7c5b8d9f6d-h2lwn   1/1     Running   0          10m

NAME                 TYPE        CLUSTER-IP   EXTERNAL-IP   PORT(S)   AGE
service/kubernetes   ClusterIP   10.96.0.1    <none>        443/TCP   1d

NAME                  READY   UP-TO-DATE   AVAILABLE   AGE
deployment.apps/web   3/3     3            3           40m

NAME                             DESIRED   CURRENT   READY   AGE
replicaset.apps/web-5d8f7c6b9d   0         0         0       30m
replicaset.apps/web-7c5b8d9f6d   3         3         3       40m
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    web Deployment와 deployment.yaml은 지우지 마세요

    3일차 첫 실습에서 오늘 만든 web Deployment에 Service를 붙입니다. kubectl delete -f deployment.yaml은 실행하지 않습니다. deployment.yaml 파일도 그대로 둡니다.

    • service/kubernetes는 쿠버네티스가 원래 만들어 두는 것이라 지우지 않습니다.
    • 실수로 지웠어도 괜찮습니다. 3일차 실습 1에서 다시 만드는 방법을 안내합니다.
    • Docker Desktop을 꺼도 클러스터 안의 리소스는 남아 있습니다. 다음 날 켜면 web Pod 3개가 다시 Running이 됩니다.
