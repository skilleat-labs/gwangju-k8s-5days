    실습 5. Deployment와 자가복구¶

    이번 실습에서 할 것

    • Deployment로 Pod 3개를 띄우고, 하나를 지워도 새 Pod가 생기는 것(재생성)을 봅니다.
    • Pod는 두고 컨테이너만 멈추면 같은 Pod에서 다시 시작되는 것(재시작)을 봅니다.
    • 포트 충돌 없이 숫자 하나로 Pod를 늘리고 줄입니다(스케일링).

    소요 시간 약 13분 (STEP 1~3 8분, STEP 4~6 5분), 교안 DAY 2 섹션 5

    준비¶

    작업 폴더로 이동합니다.

    cd $HOME\k8s-labs\day2

    cd ~/k8s-labs/day2

    VS Code에서 새 파일 deployment.yaml을 만들고 아래 내용을 붙여 넣어 저장합니다. 또는 내려받아 작업 폴더에 넣습니다.

    deployment.yaml
    apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:1.27
    deployment.yaml 내려받기

    필드 뜻
    apiVersion: apps/v1, kind: Deployment Pod(v1)와 달리 apps/v1입니다
    replicas: 3 Pod를 몇 개 유지할지
    selector.matchLabels 어떤 라벨의 Pod가 내 것인지
    template 새 Pod를 찍어낼 틀. 그 아래는 Pod YAML과 같습니다

    selector의 app: web과 template.metadata.labels의 app: web은 반드시 같아야 합니다.

    다른 터미널로 지켜보기

    터미널을 하나 더 열고 아래 명령을 켜 두면, Pod가 지워지고 생기는 순간을 실시간으로 볼 수 있습니다.

    kubectl get pods -w
# READY 확인 후 Ctrl+C

    STEP 1. Deployment 만들기¶

    kubectl apply -f deployment.yaml

    deployment.apps/web created

    Pod 3개가 모두 준비될 때까지 기다립니다.

    kubectl rollout status deployment/web --timeout=120s

    deployment "web" successfully rolled out

    Deployment, ReplicaSet, Pod를 한 번에 봅니다.

    kubectl get deploy,rs,pods


    NAME                  READY   UP-TO-DATE   AVAILABLE   AGE
deployment.apps/web   3/3     3            3           20s

NAME                             DESIRED   CURRENT   READY   AGE
replicaset.apps/web-7c5b8d9f6d   3         3         3       20s

NAME                       READY   STATUS    RESTARTS   AGE
pod/web-7c5b8d9f6d-4xk2p   1/1     Running   0          20s
pod/web-7c5b8d9f6d-9qz7m   1/1     Running   0          20s
pod/web-7c5b8d9f6d-wq8rt   1/1     Running   0          20s
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    Deployment 1개, ReplicaSet 1개, Pod 3개입니다. 이름이 web → web-7c5b8d9f6d → web-7c5b8d9f6d-4xk2p처럼 이어집니다. Deployment가 ReplicaSet을, ReplicaSet이 Pod를 만들었습니다.

    STEP 2. Pod 하나를 지운다¶

    1일차에 docker rm으로 지운 컨테이너는 그것으로 끝이었습니다. 오늘은 Deployment가 만든 Pod 하나를 지워 봅니다. STEP 1에서 본 Pod 이름 하나를 복사해 넣습니다.

    kubectl delete pod <web-로 시작하는 Pod 이름>

    예를 들면 kubectl delete pod web-7c5b8d9f6d-4xk2p입니다. 이름은 Tab 키 자동완성이 안 되면 복사해서 붙입니다. 바로 목록을 봅니다.

    kubectl get pods


    NAME                   READY   STATUS    RESTARTS   AGE
web-7c5b8d9f6d-9qz7m   1/1     Running   0          2m
web-7c5b8d9f6d-h2lwn   1/1     Running   0          3s
web-7c5b8d9f6d-wq8rt   1/1     Running   0          2m
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    AGE가 몇 초짜리인 새 이름의 Pod가 생겨 다시 3개입니다. 아무도 손대지 않았는데 돌아왔습니다. 1일차 도커의 한계 2번이 풀렸습니다.

    ReplicaSet의 Events에 누가 Pod를 만들었는지 기록이 남습니다.

    kubectl describe rs


    ...
Events:
  Type    Reason            Age   From                   Message
  ----    ------            ----  ----                   -------
  Normal  SuccessfulCreate  3m    replicaset-controller  Created pod: web-7c5b8d9f6d-4xk2p
  Normal  SuccessfulCreate  3m    replicaset-controller  Created pod: web-7c5b8d9f6d-9qz7m
  Normal  SuccessfulCreate  3m    replicaset-controller  Created pod: web-7c5b8d9f6d-wq8rt
  Normal  SuccessfulCreate  40s   replicaset-controller  Created pod: web-7c5b8d9f6d-h2lwn
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    맨 아래 줄이 지운 자리를 채운 새 Pod입니다. ReplicaSet이 "원하는 3, 지금 2"를 보고 하나를 더 만들었습니다. 지운 Pod가 되살아난 것이 아니라 이름과 UID가 다른 새 Pod입니다.

    STEP 3. 컨테이너만 멈춘다 (Pod는 그대로)¶

    이번에는 Pod는 지우지 않고 안의 nginx 프로세스만 멈춥니다. 1일차 docker kill과 비슷합니다. docker kill도 컨테이너를 멈출 뿐 객체는 남겼고, 그때는 사람이 docker start로 다시 켜야 했습니다. kubectl get pods에서 Pod 이름 하나를 골라 넣습니다.

    kubectl exec <Pod 이름> -- nginx -s stop

    예를 들면 kubectl exec web-7c5b8d9f6d-9qz7m -- nginx -s stop입니다. 다시 시작되는 순간을 지켜봅니다.

    kubectl get pods -w
# READY 확인 후 Ctrl+C

    빠져나온 뒤 목록을 봅니다.

    kubectl get pods


    NAME                   READY   STATUS    RESTARTS     AGE
web-7c5b8d9f6d-9qz7m   1/1     Running   1 (5s ago)   3m
web-7c5b8d9f6d-h2lwn   1/1     Running   0            1m
web-7c5b8d9f6d-wq8rt   1/1     Running   0            3m
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    이번에는 Pod 이름이 그대로이고 RESTARTS가 1이 됐습니다. 컨테이너가 끝나자 그 노드의 kubelet이 같은 Pod 안에서 컨테이너를 다시 시작했습니다. STEP 2와 비교합니다.

    한 일 누가 대응 보이는 변화
    STEP 2 Pod 삭제 ReplicaSet 컨트롤러 새 이름의 Pod
    STEP 3 컨테이너만 멈춤 kubelet 같은 Pod의 RESTARTS 증가
    실습 4 직접 만든 Pod 삭제 없음 지워진 채로 끝

    환경에 따라 다를 수 있음

    멈춘 직후 잠깐 STATUS가 Completed로 보였다가 Running으로 돌아올 수 있습니다. -w로 지켜보고 있었다면 그 순간이 보입니다. 몇 초 뒤 다시 보면 Running, RESTARTS 1입니다.

    STEP 4. 5개로¶

    1일차에는 frontend를 하나 더 띄우려다 port is already allocated가 나서 8081, 8082로 포트를 바꿔 하나씩 실행했습니다. 오늘은 숫자만 바꿉니다.

    kubectl scale deployment web --replicas=5

    deployment.apps/web scaled

    kubectl get pods


    NAME                   READY   STATUS    RESTARTS   AGE
web-7c5b8d9f6d-9qz7m   1/1     Running   0          5m
web-7c5b8d9f6d-h2lwn   1/1     Running   0          2m
web-7c5b8d9f6d-kx5vd   1/1     Running   0          4s
web-7c5b8d9f6d-p7bnc   1/1     Running   0          4s
web-7c5b8d9f6d-wq8rt   1/1     Running   0          5m
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    포트를 신경 쓰지 않았습니다. Pod마다 자기 IP를 따로 가지기 때문입니다. 1일차 도커의 한계 3번이 풀렸습니다.

    STEP 5. 2개로¶

    kubectl scale deployment web --replicas=2

    kubectl get pods


    NAME                   READY   STATUS        RESTARTS   AGE
web-7c5b8d9f6d-9qz7m   1/1     Running       0          6m
web-7c5b8d9f6d-h2lwn   1/1     Terminating   0          3m
web-7c5b8d9f6d-kx5vd   1/1     Terminating   0          1m
web-7c5b8d9f6d-p7bnc   1/1     Terminating   0          1m
web-7c5b8d9f6d-wq8rt   1/1     Running       0          6m
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    3개가 Terminating이 되며 사라집니다. 몇 초 뒤 다시 보면 2개만 남습니다.

    STEP 6. 다시 3개로 (선언형: 파일 기준)¶

    kubectl scale로 바꾼 숫자는 deployment.yaml 파일에 남지 않습니다. 파일을 다시 apply하면 파일에 적힌 replicas: 3으로 돌아갑니다.

    kubectl apply -f deployment.yaml

    deployment.apps/web configured

    kubectl get pods


    NAME                   READY   STATUS    RESTARTS   AGE
web-7c5b8d9f6d-9qz7m   1/1     Running   0          7m
web-7c5b8d9f6d-t4mzc   1/1     Running   0          3s
web-7c5b8d9f6d-wq8rt   1/1     Running   0          7m
    출력은 예시입니다. 이름, IP, 시간은 사람마다 다릅니다.

    운영에서는 kubectl scale 대신 YAML의 replicas 값을 고쳐 apply하는 방식을 권합니다. 파일이 곧 기록이 됩니다.

    성공하면¶

    • STEP 1: Deployment 1개, ReplicaSet 1개, Pod 3개
    • STEP 2: 새 이름 Pod가 생겨 다시 3개, Events에 Created pod 기록
    • STEP 3: 같은 이름 Pod의 RESTARTS가 1
    • STEP 4: Pod 5개 Running
    • STEP 5: 3개가 Terminating
    • STEP 6: 파일대로 3개

    막히면¶

    The Deployment \"web\" is invalid: spec.template.metadata.labels: Invalid value: ... selector does not match template labels

    selector.matchLabels와 template.metadata.labels의 라벨이 다릅니다. 두 곳 모두 app: web으로 맞춥니다. 위 deployment.yaml과 한 줄씩 비교합니다.

    spec.selector: Invalid value: ... field is immutable

    이미 만든 Deployment의 selector를 바꿔서 apply했습니다. selector는 만든 뒤에 바꿀 수 없습니다. kubectl delete deployment web으로 지운 뒤 다시 apply합니다.

    no matches for kind \"Deployment\" in version \"v1\"

    apiVersion: v1으로 썼습니다. Deployment는 apiVersion: apps/v1입니다.

    error converting YAML to JSON: yaml: line N: found character that cannot start any token

    들여쓰기에 탭이 들어갔습니다. 오류에 나온 줄 번호의 들여쓰기를 공백 2칸으로 바꿉니다. VS Code 오른쪽 아래 상태 표시줄이 Spaces: 2인지 확인합니다.

    error: the path \"deployment.yaml\" does not exist

    작업 폴더가 아니거나 파일 이름이 다릅니다. Windows 메모장으로 저장하면 deployment.yaml.txt가 될 수 있습니다. VS Code로 만들거나, 탐색기에서 보기 → 파일 확장명을 켜고 이름을 고칩니다.

    Error from server (NotFound): deployments.apps \"web-7c5b8d9f6d-9qz7m\" not found

    kubectl scale에 Pod 이름을 넣었습니다. scale 대상은 Deployment 이름 web입니다: kubectl scale deployment web --replicas=5

    STEP 3 뒤에도 RESTARTS가 0 그대로

    kubectl get pods를 너무 빨리 봤거나 다른 Pod를 보고 있습니다. 몇 초 뒤 다시 보고, exec에 넣은 이름과 같은 줄을 봅니다. STEP 3은 한 번만 하면 됩니다. 여러 번 반복하면 다시 시작 간격이 길어지며 CrashLoopBackOff가 보일 수 있습니다.

    STEP 2에서 Pod 이름을 넣었는데 Error from server (NotFound): pods \"...\" not found

    이름을 잘못 옮겨 적었거나 꺾쇠(< >)까지 같이 넣었습니다. kubectl get pods로 이름을 다시 보고 꺾쇠 없이 이름만 넣습니다.
