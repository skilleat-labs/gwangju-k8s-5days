    실습 3. 내 이미지 만들기¶

    이번 실습에서 할 것

    • Dockerfile로 내 이미지를 만들고 실행합니다.
    • docker history로 내 이미지가 nginx 레이어 위에 얇은 층 하나를 얹은 것임을 확인합니다.

    소요 시간 약 10분, 교안 DAY 1 섹션 3

    준비¶

    터미널이 작업 폴더에 있어야 합니다. 새 터미널이면 먼저 이동합니다.

    cd $HOME\k8s-labs\day1

    cd ~/k8s-labs/day1

    STEP 1. 작업 폴더 만들고 이동¶

    day1 안에 myweb 폴더를 만들고 들어갑니다.

    mkdir myweb

    cd myweb

    STEP 2. 편집기로 파일 2개 만들기¶

    VS Code에서 day1/myweb 폴더를 우클릭 → 새 파일로 아래 두 파일을 만듭니다. 이름을 정확히 똑같이 씁니다. Dockerfile은 확장자가 없고 D가 대문자입니다.

    index.html
    <h1>Hello, Gwangju!</h1>
    index.html 내려받기

    Dockerfile
    FROM nginx:1.27

COPY index.html /usr/share/nginx/html/index.html
    Dockerfile 내려받기

    • FROM nginx:1.27: nginx 1.27 이미지 위에 쌓습니다 (베이스).
    • COPY: 내 PC의 index.html을 nginx 기본 페이지 자리에 복사합니다. 새 레이어가 하나 생깁니다.

    내려받은 파일을 쓸 때는 두 파일을 myweb 폴더로 옮깁니다. 파일이 제대로 있는지 확인합니다.

    ls


    Dockerfile  index.html
    출력은 예시입니다. Windows PowerShell은 Mode, LastWriteTime 칸이 함께 나옵니다.

    Dockerfile.txt나 index.html.txt가 보이면 아래 막히면을 봅니다.

    STEP 3. 빌드하고 실행¶

    -t는 이미지 이름과 태그, 맨 끝의 점(.)은 "지금 폴더의 Dockerfile을 써라" 는 뜻입니다. 점을 빠뜨리지 않습니다.

    docker build -t myweb:v1 .


    [+] Building 3.2s (7/7) FINISHED
 => [internal] load build definition from Dockerfile
 => [internal] load metadata for docker.io/library/nginx:1.27
 => [1/2] FROM docker.io/library/nginx:1.27
 => [2/2] COPY index.html /usr/share/nginx/html/index.html
 => exporting to image
 => => naming to docker.io/library/myweb:v1
    출력은 예시입니다.

    만든 이미지로 컨테이너를 띄웁니다. 실습 1의 web이 8080을 쓰고 있으므로 8081을 씁니다.

    docker run -d -p 8081:80 --name myweb myweb:v1

    브라우저에서 http://localhost:8081 을 엽니다. 내가 쓴 Hello, Gwangju! 가 보이면 성공입니다.

    curl.exe http://localhost:8081

    curl http://localhost:8081

    <h1>Hello, Gwangju!</h1>

    docker history로 레이어 보기¶

    교안의 STEP 3 다음 장표입니다. 내 이미지가 어떤 레이어로 되어 있는지 위에서부터 봅니다.

    docker history myweb:v1


    IMAGE          CREATED         CREATED BY                                      SIZE
a1b2c3d4e5f6   1 minute ago    COPY index.html /usr/share/nginx/html/inde…   25B
<missing>      2 weeks ago     CMD ["nginx" "-g" "daemon off;"]                0B
<missing>      2 weeks ago     STOPSIGNAL SIGQUIT                              0B
<missing>      2 weeks ago     EXPOSE map[80/tcp:{}]                           0B
<missing>      2 weeks ago     RUN /bin/sh -c set -x && groupadd --sys…       60MB
<missing>      2 weeks ago     # debian.sh --arch 'amd64' …                    75MB
    출력은 예시입니다. 이미지 ID, 날짜, 크기, 줄 수는 사람마다 다릅니다.

    줄 뜻
    맨 위 줄 내가 COPY로 만든 층. 크기가 수십 바이트로 아주 작습니다.
    아래 줄들 nginx 이미지가 원래 가진 층입니다.
    SIZE 0B 파일은 안 바꾸고 설정만 기록한 단계입니다.

    내 이미지는 nginx 이미지 전체를 복사한 것이 아니라, nginx 층 위에 얇은 층 하나를 얹은 것입니다.

    성공하면¶

    • 브라우저 localhost:8081에 Hello, Gwangju! 가 보입니다.
    • docker history myweb:v1 맨 위 줄이 COPY index.html ...입니다.

    막히면¶

    failed to read dockerfile: open Dockerfile: no such file or directory

    지금 폴더에 Dockerfile이라는 이름의 파일이 없습니다. 원인은 셋 중 하나입니다.

    1. Windows 메모장으로 만들어서 Dockerfile.txt로 저장됨: 파일 탐색기는 확장자를 숨겨서 Dockerfile처럼 보입니다. ls로 진짜 이름을 확인하고 이름을 바꿉니다.

      Rename-Item Dockerfile.txt Dockerfile

      메모장으로 다시 저장할 때는 파일 형식을 "모든 파일" 로 바꾸고 이름을 "Dockerfile"처럼 큰따옴표로 감쌉니다. VS Code로 만들면 이 문제가 없습니다.

    2. Mac 텍스트 편집기로 만들어서 Dockerfile.rtf나 .txt로 저장됨: VS Code로 다시 만듭니다.

    3. 다른 폴더에서 build를 실행함: cd로 myweb 폴더에 들어왔는지 확인합니다.
    ERROR: \"docker buildx build\" requires exactly 1 argument / \"docker build\" requires exactly 1 argument

    build 명령 맨 끝의 점(.)을 빠뜨렸습니다. docker build -t myweb:v1 .처럼 띄어쓰기 한 칸 뒤에 점을 붙입니다.

    COPY failed: file not found / \"/index.html\": not found

    index.html이 Dockerfile과 같은 폴더에 없거나 이름이 다릅니다 (index.html.txt, Index.html 등). ls로 확인합니다.

    브라우저에 Hello, Gwangju! 대신 Welcome to nginx! 가 나옴

    8080(실습 1의 web)으로 접속했을 수 있습니다. 주소가 localhost:8081인지 봅니다. 그래도 같으면 index.html을 저장하지 않고 빌드한 것입니다. 저장한 뒤 컨테이너를 지우고 다시 빌드, 실행합니다.

    docker rm -f myweb

    그다음 STEP 3을 다시 합니다.

    Bind for 0.0.0.0:8081 failed: port is already allocated

    8081을 다른 프로그램이나 컨테이너가 쓰고 있습니다. docker rm -f myweb 후 -p 8082:80처럼 다른 포트로 실행하고 localhost:8082로 접속합니다.

    정리¶

    myweb 컨테이너는 더 쓰지 않습니다. 이미지 myweb:v1은 남겨 둡니다.

    docker rm -f myweb

    다음 실습을 위해 작업 폴더로 돌아갑니다.

    cd ..
