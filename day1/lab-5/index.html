    실습 5. 미니 블로그 띄우기¶

    이번 실습에서 할 것

    • 사용자 정의 네트워크를 만들고 frontend, backend 두 컨테이너를 붙입니다.
    • 두 컨테이너가 이름으로 통신하는 서비스를 만듭니다.

    소요 시간 약 12분, 교안 DAY 1 섹션 5

    준비¶

    미니 블로그 구조입니다. 이 앱을 5일차에 쿠버네티스로 그대로 옮깁니다.

    flowchart LR
    subgraph NET ["blog-net (사용자 정의 네트워크)"]
        F["frontend<br>Nginx, 화면 + API 전달"] -->|"backend-service:5000"| K["backend-service<br>Flask API, data.json 저장"]
    end
    B["브라우저<br>localhost:8080"] -->|"-p 8080:80"| F
    • 브라우저는 frontend의 8080 포트로 들어옵니다.
    • frontend는 글 저장 요청을 backend-service라는 이름으로 백엔드에 넘깁니다.
    • 백엔드는 밖에 포트를 열지 않습니다.

    실습 1의 web 컨테이너가 8080을 쓰고 있으니 먼저 지웁니다.

    docker rm -f web

    이미지 태그는 강사 안내를 따릅니다

    이 페이지는 v3-kb5 태그를 씁니다. 강사가 v4-kb5를 쓰라고 안내하면 아래 명령의 v3-kb5를 모두 v4-kb5로 바꿉니다. backend와 frontend는 같은 태그로 맞춥니다.

    Apple Silicon Mac

    v3-kb5 이미지는 Intel(amd64)용만 있습니다. M1~M4 Mac에서는 The requested image's platform (linux/amd64) does not match the detected host platform (linux/arm64/v8) 경고가 나오지만 Docker Desktop이 변환해서 보통 그대로 실행됩니다. 컨테이너가 바로 멈추거나 exec format error가 나오면 v4-kb5 태그를 씁니다 (Apple Silicon용이 함께 들어 있습니다).

    STEP 1. 전용 네트워크¶

    docker network create blog-net


    5b8e2f1c9a7d4e3b2a1f0e9d8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e1d0c9b
    출력은 예시입니다.

    STEP 2. backend 먼저 (이름 필수, 포트 공개 안 함)¶

    이름은 반드시 backend-service 입니다. frontend가 이 이름으로 백엔드를 찾도록 만들어져 있습니다.

    docker run -d --name backend-service --network blog-net skilleat/backend:v3-kb5

    STEP 3. frontend¶

    같은 네트워크에 붙이고 내 PC 8080을 엽니다.

    docker run -d --name frontend --network blog-net -p 8080:80 skilleat/frontend:v3-kb5

    docker ps


    CONTAINER ID   IMAGE                      COMMAND                  CREATED          STATUS          PORTS                  NAMES
7a6b5c4d3e2f   skilleat/frontend:v3-kb5   "/docker-entrypoint.…"   5 seconds ago    Up 4 seconds    0.0.0.0:8080->80/tcp   frontend
1f2e3d4c5b6a   skilleat/backend:v3-kb5    "python app.py"          20 seconds ago   Up 19 seconds   5000/tcp               backend-service
    출력은 예시입니다. ID, COMMAND, 시간은 사람마다 다릅니다.

    backend-service의 PORTS에는 0.0.0.0:...->가 없습니다. 밖에서는 접근할 수 없고 같은 네트워크의 frontend만 접근합니다.

    브라우저에서 http://localhost:8080 을 열고 글을 하나 써서 등록합니다. 목록에 글이 보이면 frontend와 backend가 이름으로 통신한 것입니다.

    화면 HTML이 오는지만 터미널로 확인하려면 아래처럼 합니다. 글 쓰기 확인은 브라우저로 합니다.

    curl.exe http://localhost:8080

    curl http://localhost:8080

    STEP 4. 같은 네트워크인지 확인¶

    docker network inspect blog-net


    [
    {
        "Name": "blog-net",
        "Driver": "bridge",
        ...
        "Containers": {
            "1f2e3d4c...": {
                "Name": "backend-service",
                "IPv4Address": "172.18.0.2/16",
                ...
            },
            "7a6b5c4d...": {
                "Name": "frontend",
                "IPv4Address": "172.18.0.3/16",
                ...
            }
        },
        ...
    }
]
    출력은 예시입니다. ID와 IP는 사람마다 다릅니다.

    Containers 안에 backend-service와 frontend 두 개가 있으면 됩니다.

    더 보기: 저장된 글은 어디에 있나

    백엔드는 글을 컨테이너 안의 파일에 저장합니다.

    docker exec backend-service cat /app/data/data.json

    방금 쓴 글이 보입니다. 이 파일은 컨테이너의 쓰기 레이어에 있어서, 컨테이너를 지우면 같이 사라집니다. 4일차 데이터 실습의 출발점입니다.

    환경에 따라 다를 수 있음

    이미지 버전에 따라 경로가 다를 수 있습니다. No such file or directory가 나오면 docker exec backend-service ls /app으로 폴더를 먼저 봅니다.

    성공하면¶

    • 브라우저 localhost:8080에서 글을 등록하면 목록에 보입니다.
    • docker network inspect blog-net의 Containers에 컨테이너 2개가 있습니다.

    막히면¶

    Bind for 0.0.0.0:8080 failed: port is already allocated

    실습 1의 web 컨테이너가 8080을 쓰고 있습니다. 실패한 frontend도 남아 있으니 둘 다 지우고 STEP 3을 다시 합니다.

    docker rm -f web frontend

    web을 지워도 같은 오류가 나면 다른 프로그램이 8080을 쓰는 것입니다. -p 8081:80으로 바꿔 실행하고 localhost:8081로 접속합니다. 실습 6의 8080도 그 포트로 바꿔 읽습니다.

    화면은 뜨는데 글 등록이 실패함

    백엔드 이름이 backend-service가 아니거나, 두 컨테이너가 같은 네트워크에 없습니다.

    • docker ps의 NAMES가 정확히 backend-service인지 봅니다.
    • docker network inspect blog-net에 두 컨테이너가 다 있는지 봅니다.
    • docker logs backend-service로 백엔드가 오류로 멈추지 않았는지 봅니다.

    이름이 틀렸으면 지우고 STEP 2부터 다시 합니다.

    docker rm -f backend-service frontend
    Error response from daemon: network blog-net not found

    STEP 1을 건너뛰었습니다. docker network create blog-net부터 다시 합니다. 실패한 컨테이너가 남아 있으면 docker rm -f 이름으로 지웁니다.

    Error response from daemon: network with name blog-net already exists

    네트워크가 이미 있습니다. 그대로 STEP 2로 넘어가면 됩니다.

    manifest for skilleat/backend:v3-kb5 not found / manifest unknown

    태그 오타입니다. skilleat/backend:v3-kb5와 한 글자씩 비교합니다. 강사가 다른 태그를 안내했다면 그 태그를 씁니다.

    Conflict. The container name \"/frontend\" is already in use

    이전에 실패한 frontend가 남아 있습니다. docker rm -f frontend로 지우고 다시 실행합니다. backend-service도 같습니다.
